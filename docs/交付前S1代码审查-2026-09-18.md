### N01 `plugins/web/__init__.py` 仍导入已移出出货包的模块 ← 唯一有运行期风险的

```
plugins/web/__init__.py:1:  from .framework_api import install_framework_api
```

而 `scripts/ttbox_fhs_init.sh:382-384` 会把 `plugins/web/framework_api.py` 从 payload 里 **rm 掉**。
⇒ 出货包内只要有人 `import plugins.web`，就会 `ModuleNotFoundError`。

（`lifecycle.py`、`standard.py:50-66`），不是 import 插件包；全仓也搜不到 `import plugins.web`。
所以是**潜伏陷阱**，不是现症。

**修法二选一**：① 删掉这一行（`__init__.py` 留空或只留 `__all__ = []`）；
② 把 `plugins/web/__init__.py` 也一并从 payload 排除。

### N10 `core/build-host` 是"中文路径陷阱"，会产出假失败

它把 `TTBOX_RKNN_API_HEADER` 烧成 **UTF-8 的中文路径**
（`G:/WORKBUDDY工作区/…/core/third_party/rknn/rknn_api.h`），MinGW/ucrt 的**窄字符文件 API
按 ACP 解释这串字节** ⇒ 文件打不开 ⇒ 两个读文件的用例必挂：

- `input_quant_enum_mirror_against_real_header`（`core/tests/test_input_quant.cpp:337` `!text.empty()`）
- `config_loads_existing_default_json`（`core/tests/test_config.cpp:64`）

我做了最小实验坐实（不是回归）：

```
硬编码 UTF-8 字面量路径  → fopen = NULL
硬编码 ASCII 字面量路径  → fopen = OK
exe 里烧的路径字节       → 确为 UTF-8（"工" = E5 B7 A5）
core/build-j 里同一条 ctest → 28/28 全过（该树用 ASCII 路径 C:\ttbox-local 配置）
```

`C:\ttbox-local` 是指向本工作区的**符号链接**（16:36 建），这就是规避手段。
**建议**：要么删掉 `core/build-host`，要么在流程文档里写死"跑 ctest 用
`C:\ttbox-local\core\build-j`"。否则每个后来者都会在这里白折腾一轮。
