## 四、本轮修正与发现

### F0 · ★ 真缺陷（已修）：发布树 `usb-proxy` 丢可执行位

| 项 | 内容 |
|---|---|
| 现象 | 首次发布 1.3.0 后 `ttbox-usbproxy.service` 反复重启 ⇒ `failed`；`run-ttbox-usb-proxy.sh` 预检直接 exit 1：`Stopped: usb-proxy is not executable: /opt/ttbox/current/usbproxy/usb-proxy` |
| 根因 | `usb-proxy` 是**预编译 ELF、无 shebang** ⇒ MSYS/Git-Bash 判定其非可执行（源侧 `0644`）⇒ 同步/tar 原样把 `0644` 带进 payload ⇒ release 树不可执行。**（同批 `plugins/*/bin/*` 与 `scripts/*.sh` 都有 shebang，未被波及；`scripts/wifi_manager.py` 由 `install -m 0755` 显式赋权。）** |
| 为何能穿过门禁 | `ttbox_release_install.sh` step5b 的 unit 断言**只查 `ExecStart` 首 token 可执行**（= `usbproxy/board/run-ttbox-usb-proxy.sh`，has shebang ⇒ 0755），**不查**它内部 `exec "$PROJECT_DIR/usb-proxy"` 的那个二进制 ⇒ 该缺陷在发布门禁下**静默通过** |
| 处置 | `scripts/ttbox_fhs_init.sh`：在 usbproxy `tcopy` 后**显式 `chmod 0755 -- "${payload}/usbproxy/usb-proxy"`**（带成因与"为何穿过门禁"的注释）；重发布后 **5 服务全 active** |
| 复现场景 | **换新板 / OTA 首装**必现（源树凡从 Windows 侧同步即触发）⇒ 属商业化阻断项，已修在仓库脚本 |

### F1 · 真环境陷阱（已清）：残留 `license.key` 遮蔽 store

| 项 | 内容 |
|---|---|
| 现象 | B5 首轮 FAIL：激活当次绿灯，**重启后回落 `unactivated`** |
| 根因 | 恢复链优先级 `--license > /etc/ttbox/license.key > config > store`（**覆盖优先，设计如此**）。板端残留一个**旧开发卡串** `/etc/ttbox/license.key`（`LS-CF3911E9-…`，与已退役的旧 `license.json` 同批放置）⇒ 它**遮蔽**了刚激活并落盘到 store 的合法卡；该旧串非合法 Ed25519 信封 ⇒ 被拒 ⇒ 未激活。core 日志铁证：`授权卡号已加载 (prefix: LS-CF391...)` |
| 处置 | 备份至 `/root/license-backup-20260917T062241Z/etc-license.key`，改 `license.key.v1-retired`；同时 store 里的旧 `license.json` 早前已改 `license.json.v1-retired`。**清后 B5 稳定通过（就绪 t+2s）** |
| 运维要求 | B 系列验收前必须 `test ! -e /etc/ttbox/license.key`（见清单 §2 陷阱 3）。**fhs_init 不创建也不管理 `license.key`（正确：它是运维覆盖入口）** |

## 五、两个板端陷阱（判定纪律，已固化进脚本）

1. **回落绿灯（假 FAIL 源）**：`ttbox-web.py::_license_block()` 在**读不到 core IPC** 时返回"诚实未激活默认块"。core 重启期间 IPC 未就绪 ⇒ 此时读到的 `unactivated` **是 web 回落，不是 core 判定**。**规避**：判定前用**直连 `/run/ttbox/core.sock` 的 IPC PING**（`"pong":true`）作就绪探针，**禁止固定 `sleep`**。
2. **systemd 启动限速（假 FAIL 源）**：`ttbox-core.service` = `Restart=always` + `StartLimitBurst=5`/`StartLimitIntervalUSec=5min`。验收每轮重启 2 次，连跑数轮即打满配额 ⇒ `start-limit-hit` ⇒ systemd 拒启，被误读成"core 起不来"。**规避**：每次重启前 `systemctl reset-failed ttbox-core`。

> 两个陷阱均已内建进 `scripts/ttbox_m2_license_accept.py`（可复用验收驱动，带注释说明，勿删）。
