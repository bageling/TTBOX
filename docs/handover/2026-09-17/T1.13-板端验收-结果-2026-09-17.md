### A24 比特级等价（本轮最强证据）
用 imgdetect 双变体（兼容 I/O 基准 vs `init_zero_copy` + XOR 0x80 真快路径）在
**同一帧、同一模型**下对比全部输出张量：

- 320dawan0907（INT8/NHWC/AFFINE/zp=-128，9 输出）：**9/9 张量 0 字节差异**
- EP（INT8/NHWC/AFFINE/zp=-128，6 输出）：**6/6 张量 0 字节差异**

> 判定强于 A24 规格（框数±1/分数差<0.05/IoU>0.9）——直接比特等同。
> 注：测试帧（当前 HDMI 画面）无目标域内容，检测数两路同为 0（一致）；
> 路径级正确性由状态位 + 比特级张量对比钉死。
> **★ 探针发现的契约事实（记档）**：`set_input()` 零拷贝分支是裸 memcpy，
> XOR 0x80 重映射职责在 WorkerPool/RGA 层——探针必须自己 XOR 后喂入才得到一致输出。
> 误喂未重映射数据会得到垃圾输出（87% 字节差）且**不报错**——上层调用契约须遵守。

## 四、本轮修掉的 3 个真实缺陷（全部已修仓库 + 同步板端）

1. **非登录 SSH umask 077 ⇒ release 树 0700 root**：fhs_init/release_install 的
   `mkdir/install -d` 继承调用方 umask，plink（umask 077）跑出 0700，
   `User=ttbox` 的 web/preview 200/CHDIR。修复：两脚本头部 `umask 022` +
   `stage_payload` 显式 `chmod 0755`（tar 会把 payload 根 "." 的 mktemp 0700 还原给 release 根）。
2. **`usbproxy/usb-proxy` 丢失执行位（0644）**：此前同步时执行位被剥，旧进程一直活着
   掩盖了它，本轮重启才炸。已 `chmod 0755`（sha256 校验 OK）。根因在文件传输环节，出货打包
   （tar 保留权限）不受影响。
3. **payload plugins 包残缺**：fhs_init 只拷 `plugins/web`+`plugins/preview`，
   而 `framework_api.py` 要 `from plugins.system_host import …` ⇒ release 树里
   web 启动即 ModuleNotFoundError。修复：整树 `tcopy plugins`（bin/ 闭集 A7 不受影响）。
