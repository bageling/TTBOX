# TTBOX 回滚机制 (Rollback)

## 1. 概述

TTBOX 运行在 RK3588 平台，不支持标准 A/B 分区 OTA。本方案使用**备份 + 原子切换 + 错误恢复**策略实现可靠回滚。

## 2. 回滚策略选择

| 策略 | 支持 | 说明 |
|------|------|------|
| 真 A/B 分区 | ❌ | RK3588 启动分区不足以支持双系统 |
| 备份 + 原子切换 | ✅ | 主方案 |
| 完整系统镜像 | ⚠️ | 保留用于手动恢复 |

## 3. 备份策略

### 更新前备份

```
更新前状态
    ↓
备份至 /var/lib/ttbox/update/backup/v{current_version}/
├── files/
│   ├── usr/local/bin/ttbox-core
│   ├── usr/local/bin/ttbox-web
│   ├── etc/ttbox/ttbox.conf
│   └── lib/systemd/system/ttbox-core.service
├── manifest.json
├── package.json
├── checksums.sha256
└── backup_complete.flag
```

### 备份内容

| 内容 | 必需 | 说明 |
|------|------|------|
| 二进制文件 | ✅ | Core、Web、Gateway |
| 配置文件 | ✅ | 自动迁移前备份 |
| Systemd 服务 | ✅ | 服务定义 |
| 模型列表 | ✅ | 不备份模型文件本身 |
| 用户数据 | ❌ | 单独备份在 profiles/ |

## 4. 原子切换

使用了符号链接切换：

```bash
# 安装新版本到 /opt/ttbox/active/
# 指向不同版本目录

/opt/ttbox/
├── releases/
│   ├── v0.1.0/    # 旧版本（当前运行）
│   └── v0.1.1/    # 新版本（staging）
└── active → v0.1.0  # 符号链接

# 更新步骤：
# 1. 解压新版本到 v0.1.1/
# 2. 验证完整性
# 3. 创建备份
# 4. 切换符号链接：active → v0.1.1
# 5. 重启服务
# 6. 健康检查
# 7. 如果失败：切换回 active → v0.1.0
```

## 5. 回滚流程

```
┌─────────────┐
│ 检测到失败   │
└──────┬──────┘
       │
┌──────▼──────┐
│ 停止服务     │
└──────┬──────┘
       │
┌──────▼──────┐
│ 检查备份存在 │ ← 不存在 → 紧急恢复模式
└──────┬──────┘
       │
┌──────▼──────┐
│ 恢复文件     │
└──────┬──────┘
       │
┌──────▼──────┐
│ 恢复配置     │
└──────┬──────┘
       │
┌──────▼──────┐
│ 恢复服务     │
└──────┬──────┘
       │
┌──────▼──────┐
│ 启动服务     │
└──────┬──────┘
       │
┌──────▼──────┐
│ 健康检查     │
└──────┬──────┘
       │
┌──────▼───────┐
│ 标记回滚完成  │
└──────────────┘
```

## 6. 回滚触发器

| 触发条件 | 行为 |
|----------|------|
| 健康检查失败 | 自动回滚 |
| 服务启动失败 | 自动回滚 |
| 用户手动请求 | 手动回滚 |
| 启动时检测到 APPLYING 状态 | 自动回滚 |
| 版本不匹配 | 自动回滚 |

## 7. 回滚类型

### 自动回滚

- 更新过程中发生错误
- 健康检查失败
- 无需用户干预

### 手动回滚

- 用户通过 UI 或 API 请求
- 版本回退到上一版本
- 保留当前版本备份

### 紧急恢复

- 备份丢失或损坏
- 需要手动上传恢复包
- 通过 OTG 或 TFTP 恢复

## 8. 回滚能力限制

| 限制 | 说明 |
|------|------|
| 回滚深度 | 仅支持回滚到上一个版本 |
| 配置迁移 | 回滚时恢复旧配置，不保证新配置兼容 |
| 模型兼容 | 回滚不涉及模型版本 |
| 数据保留 | 用户数据始终保留 |

## 9. 回滚测试

```
测试用例：
1. 正常更新后回滚
2. 健康检查失败自动回滚
3. 应用阶段断电后自动回滚
4. 无效包安装后回滚
5. 手动回滚到指定版本
```

## 10. 灾难恢复

如果系统无法启动：

1. TFTP 网络引导恢复模式
2. USB OTG 恢复包
3. SD 卡启动恢复系统
4. 串口 U-Boot 命令行恢复

这些作为紧急方案，不包含在常规 OTA 更新流程中。
