## 2. 物理 report 解析

**PARTIAL**

公开源码的基础透传路径不按鼠标语义解析 X/Y，只把 interrupt report 作为字节缓冲区透传；注入规则层 `apply_operations()` 可以按 offset/size 对 report 做字节级修改。

生产二进制运行日志进一步确认鼠标 report descriptor 已解析为：

## 4. MOVE → merge 证据

**PARTIAL**

生产二进制字符串确认以下流程存在：

```text
mouse-control: inferred physical HID layout from first report
mouse-control: inferred physical HID layout from first overlay report
mouse-control: enabling physical overlay after Windows HID ready grace period
mouse-control: physical overlay waiting for Windows HID host readiness
mouse-control: forwarding physical overlay reports to Windows (dx=%d dy=%d wheel=%d buttons=0x%02x)
mouse-control: active HID layout is outside report length, dropping injected report
mouse-control: active HID layout has no wheel field, dropping injected wheel delta %d
```

由此可确认：

```text
mouse-control MOVE
→ physical overlay report
→ 使用已解析的 HID layout
→ 将 dx/dy/wheel 写入 overlay report
→ 进入 USB 输出路径
```

但当前生产二进制为加密包解密到 memfd，`mouse-control` 的内部函数名和精确队列变量没有可读符号，merge 函数地址尚未恢复。

## 6. 物理与 AI 是否合并

当前只能按证据分级：

### A：只有物理鼠标

```text
usb-ep-read → physical report → data_queue → ep_loop_write → raw-gadget
```

源码层：**CONFIRMED**。

主机光标实际移动：**NOT TESTED**。

### B：只有 mouse-control

```text
cmd.sock → usb-mousectl → physical overlay report path → endpoint writer
```

控制线程、HID layout、physical overlay 日志：**CONFIRMED**。

单独 MOVE 是否最终写入 raw-gadget 并导致主机动作：**UNKNOWN**。

### C：物理 + AI 同时存在

当前生产二进制字符串明确使用：

```text
physical overlay
forwarding physical overlay reports
```

因此存在“在物理透传报告上叠加 AI 增量”的正式设计证据：**PARTIAL**。

但尚未恢复：

```text
物理 report 与 AI delta 的精确合并时序
同一帧同时到达时的锁顺序
是否先合并再入队
是否 AI delta 单独生成 report
是否物理 report 被暂存/覆盖
```

这些保持：**UNKNOWN**。
